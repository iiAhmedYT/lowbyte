# Contributing

## How correctness is established here

Generated bytecode has to behave exactly like the JDK's. Nothing here is asserted from
first principles when it can be measured instead.

- **Differential testing.** `src/test/resources/javac21` holds real javac 21 output and
  what each sample printed on a real JDK 21. The same classes are downgraded to 17, 11, 9
  and 8 and must print the same thing every time.
- **Behaviour, not instruction counts.** javac's desugaring differs between builds of the
  same release, so tests compare output against a recorded baseline.
- **Mutation checking.** Before trusting a test, break what it covers and watch it fail.
  Several tests here exist because a mutation slipped through.
- **Run it on a real JVM.** Not optional below Java 9. See below.

## Regenerating the fixtures

`sources/` is hand-written and the only thing you edit. `generated/` comes from:

```sh
./gradlew regenerateJavac21Fixtures
```

That compiles and runs each sample on a JDK 21 toolchain, writing `<Name>.classes.zip` and
`<Name>.baseline.txt`. The archive's entries are the class list, so there is no separate
manifest to disagree with them.

- Archives are sorted, fixed-timestamp and uncompressed, so an unchanged sample regenerates
  to identical bytes. **A no-op regeneration should leave `git status` clean.** If it does
  not, something has become non-reproducible.
- A **new** sample must also be named in `Fixtures.SAMPLES`, `API_SAMPLES` or `EXCLUDED`.
  `FixtureLayoutTest` holds those lists to `sources/` both ways, so an unlisted sample fails
  rather than quietly never running.
- Samples must be deterministic. Identity hashes, `Set.of` order and anything else the JDK
  may vary have to be masked, sorted, or printed as character codes.
- `toolchain.txt` records which JDK built the current generation, so regenerating elsewhere
  shows up in the diff instead of catching someone out.

## Verifying on a real Java 8

```sh
./gradlew verifyOnJava8
```

The unit tests run on Java 17, which links `StringConcatFactory` and accepts
`invokeinterface` on a private method. **A downgrade that would die on Java 8 passes them
in silence.** This runs every sample downgraded to 8 on a real JDK 8 and compares it to the
Java 21 baseline. It is how the missing rewrite behind a lambda in an interface was found.

`check` runs it wherever a JDK 8 resolves, so `gradlew build` covers it. Where none can be
had it skips and says so; `-PrequireJava8` turns that skip into a failure, which CI sets.

Run both anyway. Neither is a superset of the other: an `invokestatic` carrying a plain
method reference to an interface method ran fine on 8 and threw `IncompatibleClassChangeError`
on 17.

## Adding a feature transform

A transform lowers one language feature the target cannot express.

1. Implement `FeatureTransform` in `transform/`. `introducedIn` is the release the feature
   arrived in; it runs only below that.
2. Add it to `FeatureTransforms.ALL`. Order within a release matters, since the list folds
   outermost-first. The comments there say which way round.
3. Add a `.java.txt` sample exercising it and regenerate.
4. Add the target to `Javac21DowngradeTest.TARGETS` if it needs a lower one.

**Frames are written by hand.** `COMPUTE_FRAMES` would make ASM load the classes being
processed, which are not on the plugin's classpath. Generated code either stays simple
enough for `Bytecode.sameFrame` or spells its frames out in full, so keep the operand stack
empty at every branch target and park values in a local across a jump.

Anything that cannot be lowered must call `onUnsupported` and leave the construct alone.
Emitting something that will not run is worse than refusing to.

## Adding an API rewrite

Rebuilds one JDK call from what an older release already had. See [APIs.md](APIs.md) for
what exists and why the list is short.

1. Write it in `api/rewrite/`, one file per JDK type: `ListRewrites.kt`, `MapRewrites.kt`.
2. Extend `InlineRewrite` (a few instructions, written into the calling class) or
   `RuntimeRewrite` (a loop, decoder or helper type, on the injected utility).
3. Add it to `ApiRewrites.ALL`.
4. Add cases to `ApiConversionSample.java.txt`, or `RuntimeApiSample.java.txt` for a
   `RuntimeRewrite`, and regenerate.

A `RuntimeRewrite` names a utility method and needs nothing else: owner, descriptor and
release all come from its `@LowbyteInfo`, so no Kotlin can fall out of step with the Java.

- `introducedIn` decides whether a call is rebuilt. `ct.sym` is not consulted, so rewrites
  work on a JDK that cannot supply one. Add the release to
  `ApiIndexTest.everyRebuiltApiArrivedWhenTheTransformSaysItDid`, which checks it against
  `ct.sym` both ways.
- Only rewrite where the observable contract matches. If the older equivalent differs on
  nulls, duplicates, mutability, ordering or exceptions, leave it to be reported.
- **Never rewrite an overridable instance method.** Forwarding to the utility is a static
  call, so any override is bypassed. Safe targets are static methods, methods on final
  classes, and rewrites that emit a call to an older method so dispatch is preserved.
  `InputStream.readAllBytes` looked fine and was not: `ByteArrayInputStream` overrides it.
- If an inline rewrite needs a scratch local, work its slot out from the descriptor rather
  than hardcoding one. The arguments below it differ per call, so a fixed slot works until
  the first rewrite with a different signature overwrites an argument with it.
- Test the boundary at a target *between* releases. Everything is below 9 at target 8, so
  target 8 alone cannot tell a correct release from a wrong one.

## Adding a utility method

For calls needing a loop, a decoder or a helper type, write Java in `src/runtime`:

```java
@LowbyteInfo(owner = "java/lang/String", name = "isBlank", descriptor = "()Z", introducedIn = 11)
public static boolean isBlank(String value) {
    return value.codePoints().allMatch(Character::isWhitespace);
}
```

That source set compiles at `--release 8`, so it has to be Java 8 code.

The annotation describes the call being **replaced**, not your method, which is always
`static` either way:

- **Static call:** take the same parameters it does. `Map.of` and
  `Objects.requireNonNullElse` work this way, as does most of the utility.
- **Instance call:** take its receiver as your first parameter, as `isBlank` does. That is
  already the operand order at the call site, and the shape an unbound method reference
  wants, so forwarding is a swap of owner and opcode with nothing generated.

Get it wrong and the operand count stops matching, failing at class load with a
`VerifyError` rather than misbehaving quietly.

Prefer an inline rewrite for a couple of instructions, like `Optional.isEmpty`. Then add
cases to `RuntimeApiSample.java.txt`, regenerate, and run `verifyOnJava8`.

## Tasks

| Task                        | Description                                                             |
|-----------------------------|-------------------------------------------------------------------------|
| `downgradeBytecode`         | Rewrites every class in the input jar to the target class file version. |
| `regenerateJavac21Fixtures` | Rebuilds the checked-in Java 21 test fixtures. Needs a JDK 21.          |
| `verifyOnJava8`             | Runs the downgraded fixtures on a real JDK 8. Part of `check`.          |
